# Design sync notes

- Source shape is `package`, but this repository is an application rather than a published component library. The converter intentionally uses the committed curated source entry `.design-sync/entry.ts`; `componentSrcMap` defines the public visual surface while the entry also exposes required preview providers and deterministic fixture hooks.
- `npm run build` outputs the application into `../app/static/dist`; it does not create a reusable package entry or declaration tree. The sync therefore relies on source-level contracts. Generated `.d.ts` files currently use permissive index signatures, so future syncs should add and maintain explicit `dtsPropsFor` contracts for components whose prop APIs must be strongly constrained.
- The current component surface has two source exports named `MessageBubble`. The sync exposes the newer inbox component (`src/components/inbox/MessageBubble.tsx`) and omits the older legacy bubble (`src/components/MessageBubble.tsx`) because a single bundle namespace cannot faithfully carry both under the same name.
- Theme styling is MUI v9 CSS-in-JS (Emotion, `cssVarPrefix: 'bridge'`); the component CSS is runtime-injected (`[CSS_RUNTIME]`), so `_ds_bundle.css` is a near-empty stub and the bundle is self-styling. `.design-sync/styles.css` carries the app's global body/color-scheme rules without its package-relative font import; the `@fontsource-variable/inter` stylesheet and its WOFF2 files are explicitly shipped through `extraFonts`.
- The converter's simple path resolver does not probe directory indexes. `.design-sync/tsconfig.json` mirrors the app aliases and adds explicit `index.ts` / `index.tsx` targets for directory imports; keep it aligned with the app's alias map.
- The curated visual surface uses full rich-preview authoring. It stands at 35 components as of 2026-09-17; `MessageTone` is the newest and exposes the sentiment axis the inbox reads.
- Remote showcase templates are reference-only design data. Production and previews use the repository theme, real routes, role gates, and canonical Bridge snapshots; sync operations must never overwrite or upload remote template folders.
- `CreatorDashboardView` and `OperatorInboxView` accept optional read-only store seams whose `getState()` contracts are deliberately narrowed to the exact Bridge state slices each view reads. `createPreviewBridgeStore()` owns a fixed live snapshot (including connected session/Agent/System state) so dashboard and shell previews are deterministic and make no backend or WebSocket calls.
- Shell contracts now expose optional `AppAppBar.headerHeight` and `AppDrawer.mobileDrawerWidth` / `onDrawerClose`; `onDrawerToggle` remains an optional compatibility fallback on `AppDrawer`.
- The production `App` owns its `ThemeProvider`, `BrowserRouter`, and live WebSocket lifecycle, while the design-agent runtime expects externally wrapped, deterministic compositions. It is intentionally excluded from `componentSrcMap`; use `AppShell` plus individual views for prototypes.
- Inter ships as the `@fontsource-variable/inter` optical-size files (`extraFonts`), covering weights 100–900, so every theme weight renders a real face. Three unreferenced static files from an earlier sync (`fonts/Inter-Regular.woff2`, `fonts/Inter-SemiBold.woff2`, `fonts/Inter-Bold.woff2`) were deleted on 2026-09-17; since 2026-09-18 the remote `fonts/` directory holds `fonts.css`, the seven Inter optical-size WOFF2 subsets and three Space Grotesk subsets. Orphans like these never appear in the diff, so removing them needs a deliberate delete.
- Known preview-state coverage limits (v9 re-grade, 2026-07-24):
  - `AppDrawer` — the permanent desktop rail is `sm`-gated (`display` xs:none/sm:block) and cannot share a capture viewport with the open mobile drawer (which needs an `xs` width). One viewport per component, so only the expanded mobile drawer is captured standalone; the collapsed desktop rail is shown in context by the `AppShell` preview. A former `DesktopNavigation` story was dropped because it rendered blank at the narrow viewport.
  - `QueryInput` — the send `IconButton` is `disabled={disabled || !text.trim()}` and the component owns its text state with no seed prop, so the enabled (accent) send affordance cannot render statically; the `Ready` cell truthfully shows the empty ready-to-type resting state. To showcase the enabled send, the component would need an optional `defaultValue`/`initialText` prop (deferred — out of sync scope).
  - `MessageStreamPane.ActiveConversation` — container height is sized so the fixture's messages fit without overflow; too short a height triggers the component's auto-scroll-to-latest and clips the top "Start of available history" control.
  - `BrandMark` — the wordmark is hidden below the `sm` breakpoint, so its capture viewport must be at least 600 px wide.
- `KpiCard` and `KpiCardSkeleton` no longer exist in source; their remote component folders are gone.
- `CreatorDashboardView` reads Full analytics readiness through its optional `activationApi`; dashboard and shell previews pass `createPreviewActivationApi()` so they make no backend calls.
- `SectionHeader` and `SettingRow` share `src/components/ui/SettingsSection.tsx`; `SetupPrompt` and `RecentConversations` render router links and need `MemoryRouter` in previews.
- Previews and designs must take MUI primitives (`Box`, `Stack`, `Typography`, `Button`, `Alert`, `Chip`, …) from the bundle package, never `@mui/material`. The preview compiler bundles `node_modules` imports as a separate MUI copy whose theme context never sees the bundled `ThemeProvider`, so it renders stock MUI (Roboto, uppercase buttons, white `background.default`). `entry.ts` re-exports the glue primitives and `componentSrcMap` maps each to `null`.
- `.design-sync/styles.css` mirrors the app's `GlobalStyles` in `src/App.tsx`: body font stack, `background.default` and `text.primary` through `--bridge-palette-*` variables, and `border-box` sizing. Without the body font, the `kpi` and `metric` variants (no `fontFamily` of their own) fall back to the browser serif.
- `ConversationInsightsPanel` previews use fixed-height containers; its capture viewport is 420x800 so the active cell is not clipped.
- The extension popup and desktop setup page consume `src/theme/generated/static-tokens.css` (`--dipsy-*` custom properties) rather than the React bundle. The sync does not ship that file yet; the conventions describe the variables so designs for those surfaces stay on the same tokens.

## Re-sync risks

- Component inclusion is explicit in `componentSrcMap`; newly added visual exports will not appear until that sparse map is extended deliberately.
- Grades follow the authored previews and config, not component source. A component whose source changed keeps its grade and skips capture, so spot-check source-changed components with `package-capture.mjs --components <names> --spot-check-components <names>` (`git diff --stat <last sync commit>..HEAD -- src/components src/layouts src/views src/common` lists them).
- `dtsPropsFor` bodies do not follow source. On 2026-09-18 `Panel` lacked `emphasis` and `arrivalStep`, `StatusChip` lacked `settled`, `AppDrawer` lacked `headerHeight`, and `SectionHeader` and `SettingRow` lacked `sx`, although the conventions header already named Panel emphasis. Compare each override with the source `Props` type whenever that source changes.
- Source-level synthesized bundles have weaker automatic `.d.ts` extraction than a published package. Re-check generated contracts after component prop changes and keep `dtsPropsFor` overrides current. The output format emits a non-generic `<Name>Props` interface, so `AsyncContent<T>` is deliberately represented with `any[]` to preserve callback usability; `Panel.sx` structurally approximates the serializable object/callback/array subset of MUI `SxProps` because the uploaded contract cannot depend on MUI package types.
- Application views and layout components may depend on Zustand stores, router context, or browser APIs. Their authored previews must own deterministic fixtures/context and must not make live backend or WebSocket calls.
- Preview data must remain static and representative; keep `createPreviewBridgeStore()` timestamps, UUIDs, counts, and message fixtures fixed. Update its canonical snapshot deliberately when protocol contracts change rather than seeding production singletons during render.
- The modern shell preview initializes the bundled singleton transport store once through the idempotent `seedPreviewShellStore()` helper to make its live-status chip deterministic without publishing during component render. The dashboard and Inbox previews use isolated stores instead.
- Dashboard previews are canonical-only. Unsupported commercial metrics, time-period deltas, and generated query answers must not enter preview fixtures.
- Authored cards cover representative stable states rather than every transport transition. `CreatorDashboardView` is visually graded on its canonical live desktop snapshot and `AppAppBar` on live chrome; loading, resyncing, degraded, error, and unavailable behavior is regression-tested in product tests and should gain additional cards only when isolated per-story store seams can keep multi-cell previews independent.
- The bundle assumes the repository's pinned npm lockfile and Node `>=18`; Playwright browser revision compatibility must be checked against the installed `.ds-sync` Playwright package before validation.
- The body font stack in `.design-sync/styles.css` is a literal copy of `typography.fontFamily` in `src/theme/tokens.json`; update both together.
- A new preview that imports from `@mui/material` renders unthemed without any build or render warning. Check `import` lines when adding previews.
- Known warnings: validation reports `FONT_MISSING` for `"Inter"`. It is the second family in the stack; `"Inter Variable"` ships and renders first, so the warning is benign. Capture can fail transiently on `AnalyticsView` with "preview module evaluated to no exports" while the render check passes; a targeted re-capture of that component clears it.
- `WebAuthnAccessView` needs a viewport at least 620 px tall; shorter viewports clip the bottom of the access card.
- No network-fetched fonts or styling assets are accepted; Inter is sourced from the installed `@fontsource-variable/inter` package.
- `Disclosure` and `MessageFlagIcon` are retired; their remote cards (`components/general/Disclosure/`, `components/inbox/MessageFlagIcon/`) and preview modules were deleted on 2026-09-17.
- Every preview imports `previews/card.module.css`. The converter emits it as `_preview/<Name>.css` and links it only in that component's card, so designs never load it. It paints the card body with the app canvas because the card template's own `body{background:#fff}` overrides the `styles.css` body rule. A preview without the import renders on white, and a preview that paints `background.default` itself shows a canvas box inside the cell. Keep `background.paper` wrappers only for components that sit on a paper surface in the app.
- A retired component's delete paths include its `_preview/<Name>.css`, which exists remotely only for previews synced after 2026-09-18. A `delete_files` call reporting fewer deletions than paths sent is expected for older ones. Re-send without the missing entries only if the call actually errors.
- Fetch the remote design anchor immediately before an upload. An exported `_ds_sync.json` is only a local fallback for diff and validation; it does not prove that the remote anchor is current. On 2026-09-17 the checked-in `.cache/remote-sync.json` described 28 components while the live project held 36.
- `conventions.md` is uploaded as the README header and is the design agent's primary rulebook, so every name it uses must exist in the built artifacts. Re-validate the component names, bundle exports, `theme.effects.*` helpers, palette roles, typography variants, shell dimensions, and `--dipsy-*` properties against `ds-bundle/` and `src/theme/generated/static-tokens.css` whenever the theme or the surface changes.

## Pleasure Pass font inputs

Space Grotesk Variable is bundled through `extraFonts` alongside Inter. Numeric `kpi` and `metric` roles use it; prose remains Inter. Both CSS-only font dependencies are excluded from knip dependency discovery and checked explicitly by the font integration tests and browser captures.
