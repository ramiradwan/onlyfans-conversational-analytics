# Native Snow Brain feasibility spike

Research-only. This directory is not imported by Brain runtime and does not change pairing persistence, installation-key signing, Bridge flows, `/ws/agent/pairing`, Full-mode routing, or production dependencies.

The native Python extension wraps upstream `snow` **0.10.0**, the same crate release already qualified by the extension WASM spike, and fixes the suite to `Noise_KK_25519_ChaChaPoly_SHA256`. The wrapper accepts only the Brain static private key, the pinned Agent static public key, and the accepted companion-session prologue. It delegates all Noise cryptography and state transitions to public upstream Snow APIs.

Pinned feasibility toolchain:

- Snow: `0.10.0`, crates.io checksum `599b506ccc4aff8cf7844bc42cf783009a434c1e26c964432560fb6d6ad02d82`, upstream release commit `4bb43f50370bdb3e8b1b57814ac662864db2704f`
- Rust: `1.98.1`
- PyO3: `0.29.2`
- maturin: `1.15.0` (build-only)
- Python: repository production line `3.11`; qualification records the exact runner patch version
- PyInstaller: repository build pin `6.11.1`
- Windows target: `x86_64-pc-windows-msvc`

The native `Cargo.lock` is a reviewed supply-chain input. `.gitattributes` fixes it to LF so its byte digest is identical on Windows checkout, and the Windows job runs Cargo with `--locked` rather than regenerating dependency resolution.

`qualification-results.json` is generated by the isolated CI workflow and records the exact tool versions, Cargo lock digest, native dependency graph, extension-module digest, frozen executable digest, MV3/native transcript evidence, independent `noiseprotocol==0.3.1` oracle result, and negative-case verdicts.
