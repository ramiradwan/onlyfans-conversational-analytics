# Optional computation worker

This executable implements the private `nlp-child.v1` framed transport and existing `nlp-worker.v2` messages. It is started only by the installed native owner with explicit inherited pipes and an owner-context handle. It has no standalone activation, listener, database or network authority. Default application construction does not configure it.

`boundary_entities` version1 accepts one closed shared-boundary entity graph ABI, CPU execution and authenticated logical data bindings. It advertises only concept mentions. Configuration maps each stable `label_id` and matching `concept_id` to a separate `model_label`; output selection does not change the ordered model conditioning. Labels, descriptions and supported settings belong to the admitted profile/configuration. Missing tasks are unavailable, not empty results. Graph/tokenizer changes require a new admitted component identity.

`boundary_topics` version1 implements `message_topics.v1` with the `onnx-boundary-classification.v1` ABI and `huggingface-tokenizer-json.v1` tokenizer. Its four logical data members are encoder, classifier, tokenizer and `boundary-topic-config.v1` configuration. Only the encoder may retain `onnx-boundary-entity.v1` when sharing that exact artifact with an entity component. Both adapters share the bounded CPU runtime and unload sessions between serial components.

Topic configuration binds ordered labels/descriptions, task instructions, file identities, component policies and explicit decoding settings. [topic.rs](src/topic.rs) defines the fields, supported policies and bounds. All conditioning is retained when returning a subset. Independent sigmoid decisions use the configured temperature and inclusive threshold, support valid empty results, and emit uncalibrated probabilities or absent scores. Empty or whitespace-only source returns no findings before tokenization or inference. Up to 64 labels and findings are supported; there are no default categories or thresholds.

Both adapters reject non-null tokenizer JSON `truncation` before initialization. The streaming check validates complete JSON and unique root fields, skips vocabulary values, polls cancellation/deadline, and limits files to 64 MiB, 64 root fields and 256 bytes per root key. Topic processing rejects truncated words or excessive complete encoded input before inference. Coverage and hashes refer to the original message. Profile v2 retains homogeneous weight formats; v3 permits mixed formats with exact per-role compatibility checked during preparation.

Prepare outside the source checkout with `tools/nlp-worker/prepare.py --source <clean pinned upstream checkout> --target <fresh build directory>`. Then use Cargo with `--locked --offline -j2`; the preparation receipt binds every copied source and license. No download feature, model acquisition or runtime environment override is used. The prepared crate contains the pinned upstream source and its Apache2.0 notices; application source remains independently versioned. Ordinary application builds do not invoke this preparation or enable the provider.

The native owner must retain read-only, identity-checked artifacts and executable/runtime package observations through child drain, enforce the caller's memory/deadline policy and join the exact worker Job. An unload drops the component sessions/tokenizer; closing the process releases its CPU runtime. Cancellation cooperates between stages; an uninterruptible stage remains subject to the owner's bounded termination/join. Neither a handshake nor a preparation response grants release approval or user authorization.
