# Validate projection documents without a full SQL parse tree

The projection document remains complete JSON in the encrypted analytics database. Its `validation_header` column is generated by `ofca_json_header_v1`. Writers cannot supply or update the header independently.

The validator parses every top-level field. It parses each item of `message_enrichments` and `conversation_metrics`, then releases that item before continuing. The returned header contains empty arrays in those positions and preserves other values. Invalid syntax anywhere in the document prevents insertion. Duplicate keys and nonstandard numeric literals are also rejected.

The header supports the existing account and schema checks, and supplies the fields for query metadata. It is not a substitute for the full document. Staging and activation still verify persisted model values, digests, source identity, graph counts, and endpoint closure.

Every encrypted database connection installs the deterministic function, including backup and detached connections. A runtime without the function cannot write this schema. The migration preserves existing document bytes and recreates the same foreign keys, mutation guards, and query metadata.

Application-controlled insertion checks cancellation between array items. The original exception is restored after SQLite returns from its function call. Diagnostics do not include input JSON.

## Memory and limits

Validation retains the input string, the header, and at most the current array item. It does not allocate one SQL JSON tree containing all message analyses. An individual item or a non-array header field can still be large. This change does not bound graph construction, eliminate full-generation writes, or qualify a laptop workload.
