# Desktop startup storage

Bridge checks WebView2 before constructing the Tauri runtime, a WebView profile or Brain. Its read-only loader query must find a compatible Evergreen version. The [embedded prerequisite policy](../../shared/desktop-release/prerequisite-policy.json) owns the legacy minimum and fixed Microsoft acquisition page; a package descriptor may require a higher version. The producer rejects profiles below this common floor.

Unavailable or incompatible runtimes show a Windows-native recovery dialog. **Check again** repeats the loader query. **Get WebView2** opens only the approved Microsoft page and closes Bridge; acquisition does not authorize startup. Customers reopen the app after installation. The dialog also gives offline/managed-installation guidance. Renderer commands cannot select URLs, programs or runtime folders. Installed offline administrator-assisted recovery passed with an actually absent runtime payload; the [package README](../../packaging/msix/README.md) records its exact scope and remaining acquisition checks.

The native OS test observes the actual recovery controls and the real Bridge process. A child-local missing-runtime override tests loader failure without altering the machine's shared installation. A later ordinary installed 25H2 test used a documented exact-AUMID runtime-path override: native Close preserved retained material, and Check again admitted the real runtime in the same non-elevated Bridge after administrator repair. The compatible installed-runtime probe is a separate opt-in test. These controlled failures do not replace genuinely absent-runtime VM tests, actual online/offline acquisition or Store delivery. App Installer's external dependency applies only to its installation route. [Microsoft runtime distribution](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/distribution)

The packaged Brain acquires a process-held data-root lease before importing the configured application or constructing a provisioning store. The OS releases that lease when the process terminates. Reconfiguration exit 75 uses a new process; it does not release ownership early while the old process can still write.

Bridge acquires a native global mutex for the resolved data root before creating a WebView profile or Brain. Its activation namespace also binds the Windows user and validated delivery identity. Package version and the executable's versioned installation path do not enter that namespace. A secondary verifies the primary's process image and SID, grants foreground rights and forwards only the validated activation arguments; it constructs no WebView runtime or child.

The lock order is the native root mutex, Brain's lifetime `.ofca-runtime-writer.lock`, the existing per-store migration lock, then database connections. Startup uses the existing migration-lock implementation on a separate file for the lifetime lease. It does not recursively acquire a migration lock. A competing supported launch refuses before a migrating constructor. Bridge and Brain both hold the installer-running signal; that signal is not writer-exclusion proof.

An active instance using the old global Tauri identifier refuses new entry before profile access. The native host also reads the known per-user Inno registration without changing it. A customer-root launch from a different registered installation location requires a deliberate transition; qualification keeps its isolated root. The native conflict dialog gives Close and recovery guidance.

Before acquiring native root ownership, a customer-root launch queries the current user's other approved MSIX families, using identities embedded from the production direct and Store profiles. Windows derives each family from its Name and exact Publisher. The current family is excluded independently of version; another registered channel refuses even while stopped. Qualification and external test roots skip this package check. Query failure refuses startup before a WebView or Brain exists. The query changes no registration or retained state. Installed mixed-channel qualification, unsupported unregistered binaries and the bounded cross-installer handoff remain unfinished gates. [Microsoft's current-user family lookup](https://learn.microsoft.com/en-us/windows/win32/api/appmodel/nf-appmodel-getpackagesbypackagefamily)

The native forwarding frame is pinned to `tauri-plugin-single-instance` 2.5.3. Its process tests use real separate owners, window messages and abandonment; they refuse another namespace and a mismatched image before forwarding. This does not replace ordinary installed activation and real Chrome return qualification. The root signal uses the [global kernel namespace](https://learn.microsoft.com/en-us/windows/win32/termserv/kernel-object-namespaces); it creates no retained ownership file or account authority.

Root inspection creates no configuration, keys or databases and repairs no permissions. It distinguishes fresh, saved provisioning and configured state. A retained runtime database without configuration, orphaned WAL/shared-memory files, an unknown database layout, unsafe paths or an unavailable original key refuses boot. Configured state must reference the same four managed database paths.

Before any migrating constructor, schema admission opens each retained store with its original key and read-only SQLCipher. It reuses the migrator's exact lineage, contiguous ledger, checksums, integrity and foreign-key validation. Missing ledgers, future schemas and inconsistent checksums refuse.

An authoritative transition creates one verified encrypted auth/canonical checkpoint using SQLite backup, plus a current-user-protected copy of exact configuration and protected master-key material. Hardware-key references remain inside the encrypted auth snapshot; private hardware keys are not exported. The private, protected `.ofca-upgrade-state.dpapi` records intent only after the complete checkpoint verifies. Existing per-store `MigrationRunner` operations perform forward SQL under their ordinary locks. Completion requires all retained schemas and configuration material to validate before ordinary application construction.

Before creating that checkpoint, capacity admission requires three times the retained database and WAL sizes plus 64 MiB. Windows uses the space available to the current caller, including an enforced user quota; volume-wide free space cannot substitute for it. A failed capacity query refuses startup. This preflight does not guarantee that later writes succeed, so interrupted-write recovery remains required.

An interruption resumes forward under the recorded release and catalog target. Version 2 evidence also permits a strictly newer corrective release with the same delivery identity and an unchanged catalog prefix. The recorded prefix includes pending SQL, not only committed ledger entries. Packaged releases use the Windows-validated package version; legacy releases require a newer build-owned application version. Missing version evidence and version 1 journals retain exact-target recovery.

Corrective admission verifies the original checkpoint before atomically recording successor intent. The checkpoint remains unchanged; the journal records the latest accepted release and catalog before successor SQL runs. Changed material, missing stores, damaged checkpoints, rewritten migration history or conflicting delivery identities refuse. No auth or canonical snapshot restore operation is provided.

A partially built checkpoint can be rebuilt only while its recorded source schemas and protected material still match. Completed checkpoints are removed before normal mutations can occur; the completion journal checks regression against the latest accepted target. An unchanged launch does not create a full-data backup. Projection-only migrations use the existing encrypted per-store path without duplicating authoritative data.

One active cohort is pinned outside the ordinary recovery-file pruner; its bounded state is not a fifth database or customer authority. Completion removes it immediately, including after interrupted cleanup. Existing per-store migration backups retain their existing governed deletion-barrier restore and retention rules. Source tests cover corrective admission and interruption after successor intent; installed corrective updates remain a separate qualification gate.

Closed databases without a WAL use immutable read-only access while the root lease excludes supported writers. Databases with a WAL use ordinary read-only access so committed WAL changes remain visible. An existing private WAL index is required; its loss requires explicit recovery. SQLite can update that existing scratch index, but admission cannot mutate SQL authority or create a new index. Immutable access would miss WAL commits; see [SQLite WAL documentation](https://www.sqlite.org/wal.html).

The key helper's noncreating path verifies private-file permissions and reopens the existing DPAPI material. Its explicit test key remains confined to the existing test-mode port. Missing keys beside retained databases never cause a new master key to be generated. The isolated installed results in the [package README](../../packaging/msix/README.md) exercise original DPAPI reopening. They do not prove original hardware-key use.

Parent-lifetime observation begins before this inspection and before application construction. SQL progress, backup steps and checkpoint hashing observe cancellation. An interrupted migration rolls back its uncommitted transaction before returning; already committed migrations remain committed. Ordinary constructors and ASGI startup inherit the same supervision. The separate child-owned [bootstrap status pipe](../../shared/bootstrap-status/README.md) covers inspection and migration with bounded bytes, phase time, silence and absolute deadlines. Ready is emitted after ASGI startup completes and before Uvicorn binds the listener. It grants no listener or account authority. Closing the native parent also closes the status reader so a pending write cannot block cancellation. The Job Object remains the abnormal crash fallback.

Expected `StartupRefused` failures report the closed recovery status and return process exit 78. They do not escape into the windowed PyInstaller bootloader's exception handling. Native startup drains status before classifying an exited child. A recovery status or exit 78 selects the fixed retained-data recovery page while admission remains closed. Its guidance preserves existing data and keys, closes competing copies, and asks for a compatible approved app version or administrator help. Neither outcome automatically retries startup. Unexpected exceptions retain their existing failure behavior.

Normal server shutdown first closes the desktop coordinator's presentation admission and wakes its event streams. Their responses finish before Uvicorn waits for connections; application lifecycle cleanup then drains already accepted owner work. The real HTTP regression holds an event stream and an accepted operation open, proves new work refuses, and releases the existing operation only after cleanup has begun. Without this ordering, the held stream prevented lifecycle cleanup from starting. Installed Quit remains a separate check; its previous version9 failure receipt is retained.

Source tests cover real encrypted snapshots, process death partway through checkpointing and between store commits, forward resume, interrupted SQL rollback and parent EOF during pre-listener SQL. Native qualification tests cover separate handle ownership and normal pipe shutdown without forced Job cleanup.

The opt-in [frozen recovery test](../../desktop/src-tauri/tests/process_lifetime.rs) uses independently frozen auth32/auth33 artifacts. A creates the original DPAPI authority. The [synthetic fixture](../../tools/startup_maintenance_qualification_fixture.py) adds pending onboarding and license journal entries, a command and 150,000 messages in the supported canonical v11 lineage. This canonical fixture is historical retained state; it is not claimed to have been produced by the A binary, which bundles canonical v12. Commands are now issued through the real command service and reconstructed and validated during observation. Earlier raw-SQL fixtures used an invalid command ID and cannot establish usable pending commands or healthy transport shutdown; preserve their storage-transition receipts within that narrower scope. Synthetic pending license journal entries do not qualify actual licensed-capability continuity.

Qualification interrupts the encrypted canonical checkpoint by terminating its owned Brain, then resumes and cancels normally after auth33 commits while canonical v12 is still pending. It adds a signed synthetic publication checkpoint to the live auth33 store after that cancellation. Forward resume must retain it even though the encrypted auth checkpoint predates it. Hashes and counts verify pending work, protected text, exact configuration and the original DPAPI sidecar. A second B launch must skip full-data checkpointing. These tests qualify native frozen startup and recovery, including startup beyond 30 seconds. They do not establish installed package updates, synthetic signer acceptance by production trust, original TPM-key proof, Windows Hello or the full customer launcher journey.

These four opt-in cases also passed with Brain loaded from a signed qualification installation in WindowsApps. The harness verified actual Windows package identity and used `Invoke-CommandInDesktopPackage` with explicit private temporary roots. This qualifies that package-context execution, including original DPAPI reopening; it does not qualify ordinary Bridge activation, default-root virtualization boundaries or a registered-source update. Microsoft documents that the [debugging command's token differs from ordinary activation](https://learn.microsoft.com/en-us/powershell/module/appx/invoke-commandindesktoppackage). The temporary package, test trust entry and signing key were removed after execution.

## Installed corrective qualification

The controlled installed test uses `OFCA.Qualification.Direct` versions `1.0.6.0` and `1.0.7.0` with the same frozen Brain. It exercises package-version adoption and pending migration recovery, not a new software release or automatic delivery. Windows validates each process's actual package identity before the native harness selects the governed default root.

The fixture's `claim` operation refuses existing state, production roots and other qualification profiles. Its private marker permits synthetic data only in `%LOCALAPPDATA%\OnlyFans Conversational Analytics\qualification\OFCA.Qualification.Direct`. B starts the independent auth32 runtime there, seeds the documented canonical11 workload, then stops before normal admission after auth33 commits. Original hashes, counts and checkpoint evidence are retained outside the data root.

The B helper is `installed_b_records_interrupted_intent_in_the_governed_root`. An interrupted qualification can use `installed_b_reinterrupts_only_its_recorded_fixture` only with the original and independently inspected failure receipts. That path verifies the retained state before resuming; it creates no replacement key, configuration or checkpoint. Pre-listener parent cancellation returns process exit 1, while normal listener shutdown returns 0.

After all B processes exit, a controlled `Add-AppxPackage` update registers C. `installed_c_resumes_governed_state_after_durable_successor_intent` first cancels C after successor intent is durable. It checks that the original checkpoint inventory and manifest remain unchanged, then restarts C to complete canonical12 and verifies an unchanged relaunch without checkpointing. Pending work, original protected material and the publication checkpoint written after B's snapshot must survive.

This earlier sequence passed through package-debugging activation on the qualification host. An independent unpackaged observer reopened the same original DPAPI material and encrypted stores after C was uninstalled. Temporary registration and certificate trust were removed; the claimed synthetic root was preserved. Later ordinary-activation, profile-recovery and minimum-OS results are scoped separately in the [package README](../../packaging/msix/README.md). Package-debugging evidence does not establish those paths or customer App Installer delivery.

These opt-in tests require `BRAIN_QUALIFICATION_IMAGE`, `BRAIN_QUALIFICATION_A_IMAGE`, `BRAIN_QUALIFICATION_PYTHON` and `BRAIN_QUALIFICATION_RECEIPT_DIRECTORY`. Run each native test executable inside its matching registered package context, with `--exact --ignored --nocapture --test-threads=1`. Keep the same receipt directory and claimed root between B and C; never remove retained state to make a failed migration launch.

## Package metadata and qualification isolation

Native and backend consumers validate the immutable `desktop-release.json` against Windows `GetCurrentPackageId`. Missing metadata in a packaged process, a descriptor in an unpackaged process, identity mismatch, unknown/duplicate fields or a Store descriptor carrying a direct feed refuses. The descriptor describes executable distribution and storage; it grants no account or update authority. Update-source registration validation remains required before servicing.

Production and legacy default to `%LOCALAPPDATA%\OnlyFans Conversational Analytics`. Isolated qualification defaults to its `qualification\<package Name>` subdirectory. Qualification overrides can use a dedicated external test root but cannot adopt the production root or another qualification profile. Native and Python path selection reject aliases and installation containment before creating retained state. Native selection also avoids creating an absent root.

Bridge explicitly puts its WebView2 profile in `<resolved data root>\webview`. This is writable storage under the governed root and is independent of the versioned WindowsApps path. It is presentation state, separate from encrypted authority. Separate actual Reset, Settings Repair and independent WebView2 profile-loss tests reopened configured synthetic state without replacing authority; the [package README](../../packaging/msix/README.md) records runtime coordinates and limits. Actual hardware-key/pairing/license continuity remains unqualified. No Chrome profile is read or copied.

The fixed admission landing loads its packaged stylesheet in the document head before checking the one-use link. It uses the dark startup surface and a native-controls header throughout that check, including refusal. The native shell explicitly sets both foreground and background colors to keep loading and recovery text readable over its fixed dark window background. The landing CSP permits same-origin styles without inline styles; presentation styling grants no admission or account authority.

Private-file creation explicitly binds ownership and its sole full-control ACL to `TokenUser`, rather than the elevated token's default Administrators owner. Read-only authority inspection rejects an Administrators-only object without rewriting it. The Windows regression checks user-owned file and directory access through this session's non-elevated Explorer token, and verifies that an independent administrator-only fixture remains inaccessible and unmodified. This token check does not establish installed WebView2 startup.

The version8 ordinary-activation attempt exposed an administrator-owned qualification root left by elevated fixture construction. WebView2 reported that its profile directory was not writable, and another activation displayed the early installation error. Those attempts are failed activation evidence; the earlier package-debugging runs do not supersede them. Preserve that fixture and its original protected state. Qualify the corrected creation path with separate user-owned state before claiming ordinary activation.

Native early-failure TaskDialogs carry the `desktop.installation_unavailable` property and an `OFCA.StartupFailure.<static code>` property while displayed. Data-directory failures give access-recovery guidance; descriptor or installation failures retain repair guidance. These properties contain no paths, protocol arguments or authentication material. They provide passive local tracing before Brain or file logging is available.

An installed 25H2 test used the reused `04ca417a` qualification runtime to migrate synthetic auth33/canonical12 state to auth35/canonical14 through ordinary non-elevated launch. Fresh package `1.0.40.0`, containing the normal `3891ce63` runtime and its older catalogs, then refused that state: its observed Brain exited 78, no healthy listener appeared, and both encrypted databases, original key and configuration remained byte-identical. After removing that registration, reinstalling the exact newer-catalog package reopened all 5,000 messages, usable pending commands, journals and publication state. Quit ended both processes with exit zero. These administrative registrations required no forced package downgrade; they do not qualify App Installer delivery.

Fresh normal runtime `44f9230a` subsequently displayed the fixed recovery page through ordinary non-elevated activation of package `1.0.43.0` on 25H2 build 26200.8037. Correlated OS process events recorded its Brain exiting 78; no healthy listener appeared. Actual image review confirmed readable text on the dark background. The same protected authority stayed byte-identical, and explicit Quit closed Bridge with exit zero in 45 ms. Returning compatible package `1.0.44.0` reopened its original provisioning key, reached health in 5.42 seconds and quit both processes with exit zero in 386 ms. Both packages passed timestamped signature and 1,884-file inventory checks under temporary qualification trust. This establishes the recovery presentation and refusal path, not real pairing, hardware keys, licensed use or automatic delivery. The [package README](../../packaging/msix/README.md) records the wider qualification limits.

Contract fixtures and regeneration commands are in [shared desktop release fixtures](../../shared/desktop-release/README.md). Qualification construction does not qualify installed storage or updates; see [MSIX packaging](../../packaging/msix/README.md).

The owned Brain emits a bounded [shutdown observation](../../shared/bootstrap-status/README.md) after its ASGI lifecycle completes. The configured runtime refuses a successful drain observation if its analytics shutdown budget expires or another shutdown handler fails. Provisioning reports success only after its existing setup and grant-refresh owners close. Native servicing requires that observation, exit code zero and no remaining processes in Brain's Job Object before committing its private restart handoff. A deadline preserves containment until explicit Quit. [ADR 0056](../adr/0056-msix-packaging-and-managed-updates.md) defines the native helper and old-version admission gate. Full installed Product continuity remains separate from the native handoff fixture.
