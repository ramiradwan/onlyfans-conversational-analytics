# ADR 0057: Define optional local NLP computation and shared findings

- Status: Accepted; runtime activation requires separate qualification.
- Date: 2026-10-19
- Amended: 2026-10-26
- Extends: ADRs 0009, 0027 and 0056. ADR 0012 remains proposed.

## Decision

Permit one optional native computation worker under `native/nlp-worker/`. Brain remains the sole application writer and owns opt-in, authorization, account boundaries, source validation, scheduling and publication. The worker receives bounded text, opaque request identifiers and one pinned execution profile through private inherited pipes. It receives no database, credentials, network listener or publication authority. Conversation text never enters logs or temporary files.

The engine, CPU runtime and tokenizer remain outside the base installer. Direct MSIX uses a signed optional executable package in a qualified related set. Windows owns installation and servicing; the native host discovers exact approved identities and contains worker lifetime. Inno and Store retain base analytics and expose this optional capability as unavailable. There is no unmanaged executable fallback. A full-trust subprocess is fault isolation, not a security sandbox.

Model packs are authenticated immutable data, never executable extensions. Exact core/engine related-set compatibility and adapter artifact compatibility govern activation. Separate NLP trust metadata, hashes, sizes, durable publication sequence and withdrawal state govern acquisition. Analysis authorization authenticates neither executable nor data. Offline accepted installations may run under valid authorization; expired metadata blocks new activation. Learned withdrawal prevents execution.

Text-analysis execution uses the separate `urn:bridge-clean:text-analysis-license:v1` and `urn:bridge-clean:text-analysis-preview:v1` authorities for `text-analysis`, `text-analysis-artifact` and module major 1. Existing `analysis-run`, `analysis-artifact` and major 3 retain their meanings. Verification dispatches by exact profile, protected type, audience and purpose, with independently established organization, installation, key and seat context. Module authority never falls back to starter authority. The non-expiring preview binds one execution and its exact output-policy version without a debit.

The pinned contract inventory does not advertise runtime support. Text-analysis support uses its closed twelve-profile set and the subset required by each operation. Release identity, output policy, request meaning and original signed delivery bytes retain independent bindings. Recovery does not replace authority or renegotiate those bindings. Preview acquisition uses separate native proof and browser admission; its deadline derives from the server's first accepted preparation. Hosted envelopes contain no local work identifiers, findings, counts or source references.

Offline verification grants no worker activation, preview reservation or output commitment. Fixture trust remains non-production. Production execution stays disabled pending qualified composition, installed delivery and task quality. Module issuance also retains the released replacement-installation reissue prerequisite. Starter execution and saved-result reads do not acquire new authority requirements. Local preview admission must commit permitted output and spend atomically; an empty result does not spend the preview. Preview execution requires defined kinds, deterministic per-kind ranking and shown-only retention.

An analysis profile binds message-local topic classification and concept extraction to one joint component or two serial components. Each component identifies its compiled adapter, engine, complete artifact closure, conditioning schema and preprocessing/decoding policies. Compatible data changes require a new profile; a different adapter requires a compatible signed engine. Packs cannot supply executable adapters or arbitrary task graphs.

The `nlp-profile.v3`, `nlp-result.v3` and `nlp-snapshot.v3` families permit a nonempty declared subset of supported tasks. Earlier families retain their required task sets. Results and comparisons cover exactly the declared tasks. `analytics-findings.v2` reports each supported task as declared or unavailable; an undeclared capability has no outcome or coverage. The worker protocol remains v2. Profile signatures use distinct version-bound protected types.

The findings read endpoint accepts paired `category_task` and `category_id` parameters for one enabled category in the saved profile. Filtered reads use `analytics-findings.v3` with an exact category echo and task availability. Category filtering narrows current evidence and conversation pages before pagination; summaries, coverage, denominators and previous-window comparisons retain their date, direction and explicit conversation population. Conversation entries count all eligible messages and are selected before the explicit conversation filter. Unfiltered reads retain their existing response versions.

V3 profile validation binds complete typed artifact closures and tokenizer formats; compiled adapters check each weight file's format and role during preparation. This permits components with different heads to share one encoder artifact identity, counted once in profile accounting. V2 retains homogeneous weight-format validation. Structural acceptance grants no execution readiness or release approval.

Stable topic and concept identifiers remain distinct from model labels. Findings describe text, including negated or quoted mentions; they do not establish participant preferences or intentions. Future tone uses a separate qualified task profile and does not alter baseline sentiment.

`app/nlp/contracts.py` retains v1 semantics. The profile, versioned result and adapter modules define the boundary; the generator owns schemas under `shared/nlp/`. Requests declare exact tasks and component/profile identities. Brain rejects mismatched, missing, extra or duplicate task results. Compatibility declarations and handshake results do not authenticate a release.

Each task has an independent outcome and coverage. Missing dependencies, uncertainty, failure and partial examination never become successful empty findings. Scores are optional, finite and explicitly typed; model scores are not measured accuracy. Evidence uses half-open original Unicode codepoint offsets. Deduplicate only identical source/concept/coordinate occurrences; repeated phrases at different positions remain distinct.

Shared findings belong in existing encrypted analytics storage through a versioned record boundary. Brain binds them to account, exact source version, profile and executed component. Retention, deletion and account barriers invalidate evidence. Snapshot identity includes source validity and per-task completion/availability so findings can publish without canonical edits. Reuse initially requires exact source and profile equality. Joint conditioning changes invalidate both tasks. Analytics reads never trigger synchronous inference.

Canonical contribution storage follows ADR 0014. Its dormant repository separates durable jobs, fenced attempts and sealed source-bound result members from disposable analytics records. Exact-record replay requires current source and account checks without an Engine; it does not recreate historical generation or literal identities. No production execution route is enabled.

Explicit current-view recovery may create a paused read selection from exact canonical contributions, including after projection loss. It reconstructs the complete current source population and preserves result bytes and provenance. Final visibility shares the dependency authority gate and retains source, withdrawal, account and origin checks without requiring installed dependencies. Removal invalidates existing recovery tickets; a fresh read intent may select paused mode again without enabling processing. Reconstructed views receive new derived identities. Missing original labels or unsupported normalization remain explicitly unavailable, and retained saved metadata is unchanged.

One inference job runs across all profiles. The default resource policy permits at most two inference CPU threads including tokenizer pools. Components execute serially and unload between executions. Cancellation, exit and servicing drain or terminate the owned worker tree. Independent limits bound frames, batches, source text, windows, candidates and outputs. A qualified component may impose stricter limits than the protocol ceilings.

### Execution identity and preview

Brain owns durable canonical execution intents. Licensed account enablement creates an enrollment for automatic incremental processing; disposable queues do not own its identity. Pause preserves the enrollment. Account deletion retires it and its child work atomically; account recreation requires a new explicit enrollment. Child work binds exact source versions, profile and processing parameters. Sealed or deleted work cannot become a new execution through restart or projection loss.

Retiring processing preserves saved contributions and child receipts while preventing further execution. An explicitly selected replacement receives a new enrollment with immutable profile and authority bindings. Source deletion and retention expiry retain their erasure behavior; processing retirement does not erase saved results or release storage capacity.

An enrollment retains the exact original profile and verified identity-grant lineage within the canonical storage limit. Background identity is rebuilt from those grants with the original account, principal, role, organization and installation bindings; an HTTP session is not retained as execution authority. A current-account pointer and monotonic version order explicit commands across enrollment replacements. Command receipts are immutable and idempotent; projection reconciliation uses current canonical state rather than historical receipts. Automatic recovery selects only the current enrollment, and explicit historical recovery cannot replace another current owner. Capsules, commands and current pointers participate in canonical capacity accounting and backup identity.

For an explicit preview, Bridge retains a random UUIDv4 idempotency key before prepare. Brain atomically records its immutable scope, random job and promised contribution IDs, profile and ordered source inventory as a nonrunnable `prepared` job. Identical retries return the original identities; changed bindings conflict. Confirmation, preview reservation and `prepared` to `pending` occur in one canonical transaction. Licensed children use automatic admission. This prepared row represents intent rather than execution authority; it does not change the starter permit profile.

Preview preparation uses a compiled source-selection policy and discloses the frozen sample before confirmation. A retained capsule binds that disclosure, the original request and identity lineage to the job. Recovery reads the original receipt before checking current dependencies; it never selects another sample under an existing key. Source erasure removes detailed capsules while retaining content-free intent receipts.

The live account head is validated when preparing the inventory. Later transitions validate the exact retained members, eligibility and retention barriers; unrelated additions neither enlarge nor invalidate the frozen set. Changed or deleted members cannot be replaced under the same intent. Claiming requires an explicitly runnable state and a current attempt fence. Canonical commitment precedes projection replay; a lost response or projection does not require another inference.

Text-analysis references use separate licence and preview namespaces. Their signed-object digest covers the original compact JWS bytes; the canonical payload digest remains separate. Signed object IDs retain purpose-qualified uniqueness. `RuntimePolicy` carries the selected exact reference, independent account and installation context, and module rights. Start, resume and commitment rebuild policy and check current authority. Fallback is explicit, and update classification comes from trusted activation state rather than a caller assertion.

Final transitions acquire dependency and store-lifecycle ownership before an auth SQLite `BEGIN IMMEDIATE` reservation, then the canonical transaction. Policy construction uses the held auth connection. The reservation serializes authority writers; it is not a transaction across files. Store replacement requires process-safe lifecycle exclusion and matching store identity. Inference and downloads hold no such reservation. A canonical commit remains committed if releasing the unchanged auth transaction subsequently fails.

Preview has two initial kinds: `topic_category` and `mention_category`. Each shows one supported category summary with its complete observed evidence. Rank by distinct supporting conversations, then messages, descending; mentions next use exact occurrence count descending. Category ID ascending breaks ties. `+N` counts additional supported categories of that kind, excluding the shown category. It requires resolved assessment and complete examination of that kind's entire disclosed frozen scope. Otherwise omit the total and qualify ranking as observed support in the assessed portion. Complete retained evidence does not imply complete input examination.

Preview uses a separate versioned canonical representation. Retain selected summaries, supporting assignments or exact occurrences, source and chat references, coverage, permitted counts and immutable provenance. Declared taxonomy and input inventory remain input metadata. Examination metadata must not reveal discarded positives. Unshown findings and full candidate records remain bounded transient state, including before commitment; ordinary full-record staging is unsuitable. Evidence overflow ends before output rather than truncating evidence or substituting another category.

Permitted preview output, its manifest, job/result links and spend commit in one canonical transaction. No showable result means no output and no spend, with complete empty assessment distinguished from unavailable or incomplete examination. Deletion and projection failure never replenish admission. Installation-lifetime content-free intent and consumption receipts survive content cascades. Supported authoritative backup and restore verify one matched auth/canonical set before transitions; an older internally matching set can restore earlier local admission.

Durable store identities and a mirrored pairing incarnation bind that authoritative set. Pair coherence grants no execution authority. Supported replacement uses the process root lease; a single-store restore invalidates the pair. Matched restore verifies encrypted files, protected key sidecars, schemas, high-water values and current security compatibility before publication, preserving deletion barriers. A durable restore journal precedes either file replacement. Normal startup refuses an incomplete restore; exact recovery uses nonmigrating, noncreating store handles before normal constructors, validates both files, then establishes a fresh pair and clears the journal. Restoration refuses security-state differences rather than undoing newer denials or merging authority. This permits compatible earlier local preview admission without providing filesystem rollback protection.

Saved reads remain independent of execution authority and installed models. Shipping frozen builds retain refusal at worker execution and canonical commitment regardless of mutable environment settings until qualified release composition is approved.

## Consequences

Brain-side normalization contracts in `app/nlp/normalization.py` separate source occurrence anchors from extraction provenance. Caller-retained account namespaces and NFC literal keys produce deterministic provisional node IDs; spelling equality does not approve semantic equivalence. Keys exceeding 256 code points are rejected. Versioned mapping and publication contracts have a 65,536-byte canonical bound. Publication manifests exclude derived group IDs; groups are publication-scoped references. Source-verified per-record derivations and immutable snapshot-owned literal publications use the existing analytics store. Empty or overlong literal keys retain explicit dispositions and extraction coverage; they never become truncated keys or negative findings. Publications authenticate exact record, namespace, type/taxonomy, policy and batch identities. Source/account erasure and snapshot/record reclamation cover their payload. These contracts implement no alias resolver, semantic equivalence or runtime activation. Existing v1/v2 worker messages and readers remain unchanged.

These contracts alone grant no runtime or release authority. Synthetic adapter conformance verifies the typed boundary. Optional worker composition and execution are restricted to the test environment; production refuses injected workers even when dependencies are ready. This restriction does not change baseline processing, saved reads or inference-free publication. Installed delivery, task quality and complete resource costs require separate qualification before activation. Existing baseline results and v1 records retain their meanings.

V2 descriptors declare bounded safe-integer resource costs independently of admission policy. The default local policy retains 250 MiB download, 512 MiB installed footprint including rollback, 512 MiB additional peak memory and two inference threads. A caller may explicitly supply a separately approved local policy; profile metadata cannot raise these limits. Structural validation still checks the complete artifact closure, aggregate installed accounting and component transition requirements. Resource admission grants neither release trust nor processing authorization. Qualification must measure complete runtime, transition, temporary and rollback costs before adopting a different policy.

`analytics-literals.v1` exposes distinct occurrence, message and conversation counts with exact source references and independent extraction/normalization coverage. Paging and selection pin the normalization publication identity; percentages remain unavailable.

`analytics-findings.v4` adds an explicit grouped read. A constructor-injected registry admits immutable navigation declarations bound to the saved presentation, complete task set, taxonomies and enabled categories. Group support uses distinct-message and conversation unions before category filtering; complete-message shares retain the existing task denominators. Pagination pins the declaration identity. An undeclared grouping retains flat category reads. Navigation changes neither processing profiles nor saved generations, and grouped failures do not schedule analysis or projection recovery.

`analytics-observation-links.v1` projects message-topic and exact literal-occurrence links from saved findings. Category selection covers either task; literal selection pins its normalization publication. Mapped support counts remain distinct from extraction coverage, including unrepresentable literals. Pages bind the complete selected view identity and retain source, account, generation and retention checks. Topic links use whole-message evidence; literal links retain exact source spans. The view leaves baseline graph identities unchanged and schedules no analysis or recovery.
