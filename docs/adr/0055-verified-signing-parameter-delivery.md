# ADR 0055: Deliver independently verified signing parameters

- Status: Accepted implementation; installed transition qualification is a release gate.
- Complements: ADRs 0024 and 0054. Existing consent, account, installation, helper and recovery authority remain authoritative.

Brain owns anonymous background retrieval from the release-bound HTTPS origin and fixed publication paths. Its independent Python verifier accepts the root-authorized publisher keyset, signed catalog and exact immutable object. The authenticated companion dispatcher schedules misses and returns typed bounded dependency results. It never waits for public HTTP. A clock decision may wait at most 50 milliseconds for its owned durable checkpoint acknowledgement; timeout returns pending without cancelling the write.

The existing encrypted authentication store owns a forward-only publication migration. Sequence and signed-payload digests, signed metadata and clock high water remain independent of the disposable bounded object cache. First-use markers distinguish an unseen authority from missing checkpoint state. Metadata commits precede object promotion, so a withdrawal remains authoritative after an object or disk failure. Cache deletion cannot reset rollback protection.

Each extension worker owns one verified source, separate from encrypted installation/account signing partitions. Its narrow resolver sends only the closed signer DTO inside the existing authenticated ticket/account/installation wrapper. The extension independently verifies unchanged signed bytes using packaged public trust and WebCrypto. Compatible publication changes preserve the provider, consent revision, capture configuration, account proof and helper owner. Production packaging requires the reviewed immutable connector archive, complete public trust fingerprint, fixed origin and packaged engine. It accepts no raw-rule override, dynamic trust selection or extension public-network downloader.

Policy 3 binds activation to the browser-owned document and native request revision. Successful reads on that same document continue when backend response metadata changes or is absent. A replacement document requires fresh exact native reproduction and differential proof. Backend metadata cannot select a rule or initiate recovery.

Before reserving a page, acquisition checks current capacity and parameter readiness. Each candidate/control proof dispatch is separately counted as an identity request before it is sent. A missing publication saves a bounded reason, exact needed revision and deadline in the encrypted job, then creates one owned Chrome alarm. Dependency waits preserve cursors, page allowance, retry counts, coverage and grants. Restart explicitly resolves the job's needed revision. Arrival requests an ordinary authorized wake; it grants no account or helper authority. Pausing, revocation and owner replacement retain existing cancellation fences and drain entered saves.

Generic software builds without a live rule. Public trust and distribution resources are shipped and independently audited from archive bytes. Initial delivery and engine changes follow the reviewed software release process. Routine compatible publication needs no rebuild, pairing reset or commercial reauthorization. Installed qualification must exercise the same frozen Brain and production-shaped worker artifacts through both backend-only drift and a missing/new frontend publication transition. Unit vectors and downloader checks cannot establish that installed claim.
