# Signing parameter companion contract

An Agent advertises `signing.parameters.v1` in its existing hello. After Agent authentication and hello, `agent.signing-rule.resolve` accepts exactly `operation`, `protocol_version`, `auth_ticket`, `creator_account_id`, `agent_installation_id` and `request`. The config ticket and current tuple must match the protected session before and after the service await. Paused control-only clients do not invoke this method. Older Brain returns `unknown_method`; the new client treats that as a bounded feature refusal while retaining its healthy companion connection.

The inner `signing-parameter-request/v1` has exactly `engine`, `parameter_schema`, `source_revision`, `catalog_sequence`, `keyset_sequence` and `object_sha256`, in addition to `schema`. Revisions are exact opaque visible ASCII strings. No account identity, browser headers, cookie, captured signature, URL or command enters this DTO or public distribution request.

The closed `signing-parameter-resolution/v1` result always carries `status`, `keyset` and `catalog`. Available results add canonical base64url `object`; not-modified results add `sha256`. Pending and not-published add `retry_after_ms`. Unavailable adds that retry advice and one of `network`, `freshness`, `storage`, `verification`. Unsupported-engine adds no field. Metadata is unchanged compact JWS. Only pending/unavailable permit both metadata strings to be null. Retry advice is 1,000–300,000 milliseconds and is independent of platform HTTP 429 policy.

Brain refreshes at startup and six hours with bounded jitter. One background fetch task coalesces at most 128 needed revisions; a 30-second negative interval bounds repeated misses. Fixed path, redirect, decoded-byte and elapsed-time restrictions apply before verification. An RPC never waits for HTTP, and expected feed/storage failures keep the companion channel alive.

Publication readiness does not establish collection consent or account access. The worker refreshes known metadata on admitted connection and the periodic deadline, and explicitly resolves durable dependency revisions after reconstruction. Cached-only signer reads make no resolver request. Customer projections expose only a coarse history wait or actual engine-update requirement, leaving passive Preview, saved data and connection state independent.

Production uses `https://updates.dipsy.fi/signing-parameters/v1/` and the public trust resource packaged with Brain and Agent. Package audits check canonical trust identity from shipped JSON and its exact embedded runtime representation. Compatible signed metadata renewal retains an unchanged proved object; withdrawal or changed bytes cannot inherit proof eligibility.

Installed qualification uses `tools/signing-parameter-qualification/build_overlay.py` to create a new, explicitly labelled source copy with compiled public synthetic trust and a fixed loopback distribution origin. Its receipt records the changed source inputs and qualified native dependencies. Only the admitted installation provider and normal-app entry are collected into the frozen consumer; admission and publication producers remain outside it. Production packaging has no qualification flag or runtime trust/origin override.

`extension/qualification/parameter-installed-browser.mjs` runs the frozen Brain and audited read-only extension through real protected companion RPC, normal Legal and collection settings, and the shipping background and acquisition coordinators. An external TLS platform fixture supplies real document-bound browser requests; an immutable rc4 producer publishes the objects. The controller reads existing diagnostics and encrypted records through bounded observational CDP access. It does not invoke private acquisition work or replace the worker. Both `continuity` and `expiry` variants are required. Each records artifact hashes before and after, browser/network observations and its actual scope; a source-worker test is not an installed result.

Prepare the isolated non-CA platform certificate with `python tools/signing-parameter-qualification/prepare_platform_tls.py --directory <new-external-directory>`, then pass its `receipt.json` using `--platform-tls-receipt`. The tool refuses checkout paths and existing destinations, protects the disposable private key, and installs no CA. The browser maps the synthetic platform hostname to loopback and accepts only the receipt's SPKI; publication and grant producers remain outside the consumer.

The isolated browser admits optional permissions through Chrome's extension-settings UI API and normal extension permission API. Current Chromium requires an initial browser restart before those optional permissions expose webRequest events. This occurs before pairing, platform navigation or proof, and is recorded separately. The lane does not qualify the native permission prompt, live permission activation, TPM hardware, WebAuthn ceremony or a production-distributable synthetic package. No customer reload or package change is used for a publication transition.
